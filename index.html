The question

Chidamber and Kemerer (1994) proposed six design metrics for object-oriented classes. They checked them against measurement theory but never against real faults. So we ask: do CK metrics predict faulty classes because of design, or because they track class size?

Research questionDo CK metrics predict faulty classes because of design, or because they track class size?

The six metrics

01

WMC Weighted methods per class

How complex a class is, counted from its methods.

02

DIT Depth of inheritance tree

How many levels of parent classes sit above a class.

03

NOC Number of children

How many classes directly inherit from it.

04

CBO Coupling between objects

How many other classes it is tied to.

05

RFC Response for a class

How many methods can run when it receives a message.

06

LCOM Lack of cohesion in methods

How unrelated the methods inside one class are.

Why it's not settled

Construct“Fault” means four different things across the studies.
InternalClass size drives both scores and faults (El Emam et al., 2001). Only 2 of 4 studies control for it, and they disagree.
ExternalEach study analyses a single system; one uses student code.
ConclusionLogistic regression, linear regression and machine learning give results that are not directly comparable.
CK metrics are not proven valid independent of class size.The study that would settle it: many systems, size controlled, one shared definition of a fault.
